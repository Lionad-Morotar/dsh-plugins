# dsh-better

为原生 DeepSeek Harness 增加能力。十一个面：`/model` 选择器支持按供应商搜索并在行内平铺推理等级；输入框的模型触发器改为打开同一个选择器，模型名左侧带上 provider 名；`⌘Space` 把键盘送回输入框，键位在宿主快捷键面板里可改；输入框全选时附件一起被选中，复制成文本加绝对路径、粘贴时按路径还原成附件；输入框下方的读数行里，上下文占用环右边多一个「压缩 N 次」；被停下的那一轮轮尾多一个「继续」按钮，点一下就把 `continue` 发进去接着跑；设置里多一个「Tab 管理」页，按已注册的会话标签逐个勾选是否出现在标签栏，行首有序号、行可拖拽排序，最顶上是不可改的固定 1 号位「对话」；设置弹层、技能悬浮面板 / 参数候选与链接悬浮卡都改画成实色，不再让背景从弹窗下透出来；设置里再一个「技能别名」页，把 `wf` 这样的短词映射到 `/flow-workflow run`，输入时用原生斜杠菜单的面板选择；宿主半还往工具表里注册了一个模型可自行调用的推理等级工具，无参读取当前档位、给 id 才切换；桌面端打开右侧栏时把窗口一起向右加宽，屏幕放不下、全屏或浏览器里则保持原生推挤。

## 解决的问题

原生 `/model` 的搜索框只匹配模型名。你的 profile 里往往有多个供应商（如 `deepseek-account`、`deepseek-official`），它们的模型常常同名，于是输入供应商名时列表直接显示"没有匹配的模型"——即使该供应商下每个模型都符合你的意图。

装上本包后，输入供应商的 **id**（`deepseek-account`）、**显示名**（`DeepSeek Account`）或其中一段（`Account`、`official`）都能筛出该供应商的全部模型。模型名搜索保持原生行为不变。

同时，输入框右下角的模型触发器不再展开它自己那套二级菜单，而是直接打开同一个选择器，并在模型名左侧带上 provider 名（读作 `dsh-ddodsf deepseek-v4.1-flash`）：收起状态的触发器是唯一没有分组标题可依的地方，只写模型名时两个拥有同名 catalog 的供应商看起来完全一样。每一行右侧平铺该模型支持的**推理等级**，点哪个就按哪个提交，不必先选模型再进二级面板改等级。

行内等级徽章与点行结算遵守同一份指向逻辑，与原生结算语义一致：当前模型所在的行指向**已生效的等级**，其余行指向该模型的**默认等级**（目录未给默认时落到梯首）；弹层内点过某个徽章则该行改指向它。指向中的徽章只在光标所在行（键盘移动或悬停）高亮描边，其余行保持灰色，高亮即「点下去会生效的那个」。

## 怎么做的

DSH 的搜索发生在原生选择器组件内部，用一个模块私有函数只读 `label` 字段，外部无法扩展匹配面。所以本包注册到同一个 list slot cell（`conversation.input.overlay` + `id: command-popup`），以负 priority 覆盖原生条目，然后：

- 非 `/model` 的命令、以及 `/model` 的加载中 / 失败 / 带风险确认弹窗等状态，**原样渲染原生组件**——其他所有选择器的行为逐字节不变；
- 只有就绪态的 `/model` 列表由本包绘制，复用原生的 DOM 结构、内容哈希类名与键盘契约，仅替换行列表；
- 点击行一律按**行对象**结算（`settle`），不按索引。原生控制器会用自己那份更短的列表解释索引，按索引选会选中错行；
- 带推理等级的选择不走弹窗的 `onSelect`：它按行 id 重建选择、会丢掉等级，所以这类直接提交给会话的目录服务（`modelDirectories`），提交成功后复用宿主的令牌消费回调清掉 `/model`，再关闭弹窗。
- 输入框触发器遮蔽的是同一个 seat（`conversation.input.model`，`single` slot 只允许一个 owner）。原生的模型名来自 `conversation.input.model.label` 子 slot，只有声明它的注册者能渲染、二次声明会抛错，所以 caption 由本包从目录快照自己画：provider 显示名加模型名，provider 名称为空时回落 id，目录里找不到当前选择时回落翻译文案。markup 与类名沿用原生的，样式和原生触发器一致。

推理等级是**逐模型**的，不是全局阶梯：实测同一台机器上 75 个模型里有 5 种不同档位组合、24 个完全没有档位。没有档位的模型平铺一档都不显示，点击即提交；只有一档的也不显示（没有可选项）。

## 聚焦输入框

`⌘Space` 把键盘送回输入框，光标落在草稿原来的位置（不是开头）。在别处敲完代码、翻完文件树、或从终端里出来，一个和弦就能回到"继续打字"。

键位不是写死的：本包只向宿主的快捷键服务**声明**一条命令（`better.focusComposer`，标签「聚焦输入框」，别名 `focus input` / `focus composer` / `message input`），于是它出现在宿主的**设置 → 通用 → 编辑快捷键**（或 `⌘/` 打开的那个「快捷键」面板）里，和其他内建绑定同一张表：可录制、可清除、可恢复默认，冲突会被当场拒绝，改动按设备（web 按 origin、desktop 按 `userData/keybindings.json`）持久化。本包不自己存键位，也不自己挂 `keydown`——那样会得到一张隐形的、搜不到也改不了的键位表。

默认键位只声明宿主能承载的四个：

| profile | 默认 | 说明 |
| --- | --- | --- |
| `desktop:macos` | `⌘Space` | 桌面端原生键盘桥在任何本地处理器之前拦截已接受的组合，所以编辑器拿不到它 |
| `desktop:windows` | `Ctrl+Shift+Space` | 不用 `Ctrl+Space`：那是 Windows 的输入法切换 |
| `web:macos` / `web:windows` | `⌘⇧Space` / `Ctrl+Shift+Space` | 宿主把 `Space` 判为 `reserved`，web 上只有「主修饰键 + Shift/Alt」这一类才被接受 |
| `desktop:linux` / `web:linux` | 不绑定 | 宿主在 Linux 上对 `Space` 一律判 `reserved`；留给用户在面板里自选 |

`⌘Space` 在 web 端永远绑不上（宿主的 `bindingIssue` 先判 `reserved` 再看浏览器白名单），这是宿主的规则而不是本包的取舍；要在浏览器里用，绑 `⌘⇧Space` 或面板接受的任意组合。macOS 系统层的 Spotlight 也占着 `⌘Space`，本机实测该符号热键已关闭（`com.apple.symbolichotkeys` 里 `64.enabled = false`），所以按键能到达应用；没关掉的机器上系统会先吃掉它。

三种情况下命令让位（`pass`，不吞按键）：有弹层打开（宿主的模态判定在 macOS/Windows 桌面端被原生桥旁路，所以这条守在自己的解析器里）、输入框不在屏上（切到文件/Git 等视图时它确实被卸载）、以及当前没有会话。

## 怎么聚焦的

宿主的会话输入面 `conversation.input.for(sessionScope).focus()` 走的是 Lexical 自己的 focus，因此恢复的是草稿原有的选区；直接对 contenteditable 调 DOM `focus()` 会把光标丢到开头。可达性按宿主自己的次序探测：`uiSession.adapter.current` → `sessions.list.current`，取不到就什么都不做（绝不挑一个用户看不见的后台会话）。

"输入框是否在屏上"用宿主给的那个 div 上的一对属性判定：`[data-composer-input]` 与 `[role='textbox'][aria-multiline='true']` 写在同一个选择器里，宿主改名其中一个也不会让命令静默失效。

## 安装

profile 的 `package.json` 里加依赖与 bundle：

```json
{
  "dependencies": { "dsh-better": "link:/path/to/dsh-plugins/packages/dsh-better" },
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-web-app", "dsh-better"] } }
}
```

然后 `dsh plugin --profile <name> install`。`lib/` 已提交入库，安装态不跑构建。

## 输入框的附件选择与剪贴板

输入框里的附件栏和文本是两套东西：文本在 Lexical 编辑面里，附件栏是编辑面的**兄弟节点**。所以 `Ctrl/⌘+A` 只能选中文本——全选是编辑器自己的命令，而编辑器不拥有附件栏。同一处割裂让复制也漏东西：缩略图和文件卡片根本没有剪贴板表示，复制一个带图的草稿只能得到文字。

本包补上两件事，且不重写附件栏：

- **选中态**。全选发生在编辑器里，本包在同一个手势上给每个附件打标记，描边画在附件自己的可见面上（图片是缩略图按钮、文件是卡片本体）。标记的清除规则只有一条——任何改变选区或焦点的动作都清掉它，包括输入、方向键、`Esc`、点击（在输入框内外都算）、焦点离开输入框、附件列表变化。于是圈不会活得比它所属的文字选区更久，也就不会暗示「按退格会连附件一起删」——按退格只删文字，圈当场消失。
- **剪贴板往返**。复制时把附件的绝对路径接到编辑器已经写好的文本后面；粘贴时把这段路径还原成附件，走宿主自己的 `onAddFiles` 入口，因此图片上限、上传队列、去重与「文件」菜单完全一致。

### 剪贴板格式

一份剪贴板，两种读法：

| 类型 | 内容 | 读者 |
| --- | --- | --- |
| `text/plain` | 文本 + 空行 + 每行一个绝对路径 | 其他任何应用（终端、编辑器、另一个聊天），也是本包粘贴时的兜底 |
| `application/x-dsh-composer+json` | `{v:1, text, attachments:[{path,name,type,kind}]}` | 本输入框自己，精确还原文本与附件的分界、媒体类型和顺序 |

结构化那份是权威的：文本里可能本来就以路径结尾，靠启发式去猜会让同应用复制变得有损。没有结构化载荷时（跨应用复制一段路径列表）才退回解析文本，且规则很窄——**每一行都必须是绝对路径**，任何一行不是就整段当文本，不吞普通句子。粘贴侧的路径先经宿主的 `remote.workspaceFiles.readBytes` 读回字节（与侧栏文件预览同一条授权读取），文件超过单次读取上限时退化成 `@路径` 提及，文件已不存在则跳过并提示。

草稿**只有附件、没有文字**时走另一条写入路径：浏览器不会为空选区提交 `copy` 事件的 `clipboardData`（事件会触发、写进去的内容会被丢掉，实测剪贴板仍是空的），所以这种情况改用异步剪贴板 API 直接写一份纯路径列表。它没有结构化载荷，但粘回本输入框时正好走「纯路径列表」那条解析——媒体类型从扩展名还原，附件照样重建。

**路径从哪来**：桌面应用在 `dsh-app://` 下装了 `__DSH_HOST_PATHS__`（`webUtils.getPathForFile`），浏览器 `File` 因此能反查回磁盘路径；纯 web GUI 没有这个桥，附件也就没有路径。所以：

- 桌面端从访达拖入/选中的文件 → 有路径，复制得到路径、粘贴读回字节；
- 从剪贴板直接粘进来的截图 → 浏览器里没有来源路径，复制时给出提示「N 个附件来自剪贴板、没有本地路径，未复制」，不写任何东西到剪贴板（不会把上一份内容伪装成本次结果）；
- 纯 web GUI → 同上，复制退化为纯文本。

不做 base64 兜底是刻意的：这条功能的价值就是把「附件」表达成可读、可复用的路径，而不是把图片塞进剪贴板。要跨设备搬运图片，走文件本身。

### 怎么挂上去的

`conversation.input.attachments` 是 `single` slot，宿主自己的附件栏是它唯一的 owner。本包以负 priority 遮蔽同一个 cell，把原生组件当子节点渲染——缩略图、文件卡片、上传进度、拖放遮罩、原图灯箱全部保持宿主实现，本包只在外面加选择与剪贴板。包裹层在**没有附件时 `display: contents`**：卡片是带 `12px` gap 的 flex 列，多一个盒子会把编辑器整体下推。

描边用 `outline` 而不是 `border`/`box-shadow`：`outline` 不参与布局，标记出现与消失不引起任何回流；它画在附件自身元素的内侧（`outline-offset: -2px`），因为附件栏的轨道是 `overflow-x: auto / overflow-y: hidden` 且高度正好等于条目高度，画在外侧会被上下裁掉。颜色用 `--dsw-alias-state-business-primary`（本主题里真正承载品牌色的 token，也是发送按钮的填充色），`--dsw-alias-brand-primary` 名字像但在这个主题里是墨色，用它画出来是黑圈。

## 上下文压缩次数

输入框下方那行读数的末尾，上下文占用环（`上下文已用 N%`）右边多一个「压缩 N 次」。它回答的是与占用率相邻但不同的问题：上下文有多满，以及它被重建过多少次——一个跑了四小时却只占 12% 的会话，通常是被压缩过几次的会话，而此前屏幕上没有任何东西说过这件事。

数字来自本包宿主半注册的 `sessionCompaction` 投影（`ctx.sessionProjections`）：占用率说明上下文有多满，永远不会说明它被重建过几次，所以这个数字只能在宿主侧折叠会话日志、再作为 wire view 送到浏览器。客户端半只负责格式化。

计数口径以 `compaction/end` 为准：一次尝试只有一个收口事件，不带 `error` 记一次落地压缩，带 `error` 记一次失败。自动压缩与 `/compact` 走同一条路径，都算。另外两个候选事件都不行：

- `compaction/start` 是摘要开始前写下的持久锁，进程中途崩掉也会留下它，计进去会把没落地的尝试算成一次；
- `compaction/summary` 是提交的**第一条**事件，写在替换对话面之前——提交在两者之间失败时，catch 会补一条带 `error` 的 `end`，按 summary 计就会把没落地的压缩算成一次。

失败次数因此是「已开锁但没落地」的次数，而不是「所有被拒的尝试」：区域校验、正在压缩等检查都在写 `start` 之前抛错，这类尝试不落任何事件，读数看不到，鼠标悬停的说明也不会把它们算进去。

fork 会话只算自己的：seeded 会话的日志前缀是父会话的事件，registry 从日志开头折叠，所以 `init` 记下继承前缀长度（`inheritedEventCount`），折叠跳过 `seq` 小于它的部分。本机实测一个 seeded 会话有 8 条收口事件，其中 4 条在继承前缀里——不跳过就会把父会话的压缩算成自己的。

零次压缩时不渲染：新会话旁边常驻一个「压缩 0 次」是噪音，占用环自己也是等到有占用才出现。宿主没有 `sessionProjections` 这个 seam 时读数同样不出现，本包其余四个面照旧工作——宿主半用软探测，不是硬依赖。

键名 `sessionCompaction` 沿用 `dsh-session-timing` 的 `sessionTiming` 那个取舍：起一个描述性的新 key 就没有和宿主耦合，代价是万一上游将来也发同名投影、且 `stateVersion` 不同，注册会直接抛错（同版本则静默共享第一个注册）。选新 key 而不是接管既有 key，是为了卸载本包就干净回到上游行为。

### 为什么位置由 CSS `order` 决定

宿主把占用环硬编码在 `conversation.composer.dock` 出口之后，所以 slot 条目在 DOM 顺序上永远在环的左边；而那个出口的锚点样式是 `display: contents`，条目本身就是 dock 这个 flex 行的 item，于是 `order` 是唯一能把读数挪到环右边的开关。

`order` 只收整数，所以「环右边、面板上方」写不成一个介于两者之间的值：占用环与统计 pill 保持默认 0，docked 终端（`dsh-term-dock`）占 1 并顺带把整行变成 wrap、面板独占一行。读数因此也进 order 1 这一档，同时用 slot `order: -1` 让自己在档内排在终端之前——落点就是「环右边、终端上方」。终端 docked 时那一档的 gap 被压成 0，读数自己补 12px 左边距。

## 推理等级工具

宿主半还往工具表里注册了一个模型可自行调用的工具 `set_reasoning_effort`。它有两种调用形态：不带参数是读取，回答当前生效的档位、模型的默认档位，以及这个模型自己声明的等级 id 列表；带上 `effort` 才是切换。读取刻意做成免费的，因为模型最常需要的正是「我现在在什么档位」这个事实，如果连读都要付代价，它就只能靠猜。

切换是贵操作，贵在 provider 的 prompt cache 会整段失效：下一次请求不再复用任何缓存前缀，按全量上下文重新计费。工具描述因此只有一句话（97 字符）：读取与切换各是什么，切换会清空 prompt cache，只在用户要求时才用。工具描述每次请求都会进模型上下文，多一句就多一份常驻成本，所以「不得来回调参」「不得当重试或兜底」不逐条写进去，由「只在用户要求时才用」与工具名本身收束。

切换只改本会话从下一次 model step 起的选择，不写用户的默认模型偏好。这一点与 `/model` picker 不同：picker 改的是持久化的默认选择，下次开新会话还在；这个工具改的是当前会话的临时档位，会话结束就没了。把两者分开，是因为模型替用户改默认值属于越权，而临时调整正是它该做的事。

请求的档位与当前生效的一致时是 no-op，不落 `model/selection` 事件。这条不只是省一次写：事件落库会让浏览器半的档位文案跟着变，也会让下一次请求真的换档，等于为一次没有变化的请求付掉整段缓存。模型没有推理等级、或给的 id 不在它声明的列表里时直接拒绝，后者会把可用 id 列在错误消息里，模型据此就能自己纠正，不用再回来问用户。

注册走软探针：宿主同时有 `tools` 与 `llm` 才注册，缺任一个就静默跳过。缺 `llm` 的组合（headless）本来也跑不了这个工具，为它抛错会把本包其余面一起拖下水。`lib/index.js` 是宿主实际加载的那一半，改完源码要重建、并重启宿主才会出现在工具表里。

验证面：单测覆盖读取、切换、等值 no-op、未知 id、无等级模型、缺会话模型选择，以及 `inject` 与 `get` 两条注册路径。真机验证需要重启宿主，因为工具表在进程启动时装配。

## 停止或中断之后继续

宿主在一轮没有正常跑完时只把轮次状态画成「已停止」，没有回到那一轮的入口；进程中途退出、恢复时被补上收尾的那一轮还会多一条「任务已停止」。想接着让它说完，只能手动在输入框里再打一遍 `continue` 回车。装上本包后，那一轮的轮尾多一个「继续」按钮，点一下就把 `continue` 作为用户消息发进去，等于替你打了那七个字母。

按钮出现要同时满足三条，每一条都对应一种「出现了反而是错的」的情况。第一，这一轮的收尾必须是宿主画「已停止」的那两种：`reason.kind === "aborted"`（用户按下停止、父会话或插件取消、宿主在跑完前关闭会话）或 `reason.kind === "interrupted"`（DSH 进程退出后由恢复补写的收尾）。宿主 `TurnProcessNodeView` 的判据就是 `aborted || interrupted`，两边用同一份集合，所以不会出现状态行写着「已停止」却没有按钮、也不会按钮挂在一轮正常结束的轮次上。`aborted` 自带的取消原因（`user` / `parent` / `hook` / `disposed` / `legacy`）刻意不再细分：宿主画那一行时也不分，而且退出登录那一类在重新登录后仍然值得继续。第二，必须是当前对话的最后一轮：给历史里的停止轮挂按钮，消息会追加进用户已经翻过去的位置，看起来像发错了地方。第三，不能有未落定的提交：有的话说明用户自己已经接上了，再给一个按钮就是重复。

其余收尾（`completed`、`error`、`blocked`、`max-tokens`、`forked`）都是这一轮自己的结论，继续它们是新的请求而不是恢复，给它们挂按钮等于把每个结束的轮次都变成一个邀请。

发送走的是客户端会话，不是新开一条宿主路由。composer 的整条提交链终点就是客户端 Session 的 `prompt(content, mode)`，`conversation.sendSession` 最后也是调它，所以这里与用户敲 `continue` 回车是同一个入口，好处是本包这一面零宿主半改动。模式用 `queue` 而不是打断式提交：按钮存在的理由就是用户刚停过一轮，最不该给的是第二次打断；排队也让宿主还在收尾时发出的消息不会丢。

不做自动续跑是有意的。那是 `dsh-llm-retry-settings` 那类插件的地盘，它在 turn 结束后自动重发；本包只提供手动入口，零自动行为，两者并存不打架。自动重发与「我停了你帮我接着跑」是两种意图，混在一个开关里，用户就没法只要其中一个。

缺 seam 时整行不渲染，也不抛错。组件的全部依赖都从 slot 递进来：owner 的轮次位置值，标准套件给的 `useChat`、`useSession`、`t`，外加注册时 `inject` 的发送动作。任一缺失就返回 `null`。宿主没有这些 seam 是常态而不是故障，一行消失比一行崩掉好。两个选择器在任何提前返回之前调用，否则宿主状态一变就会破坏 hook 顺序。

与同槽位的成本读数是两个 id、两个 order（`cost-meter-turn` 是 10，`better-continue` 是 20），并存不遮蔽。同一槽位里同 id 才会互相顶掉，这里只是排在同一行的先后。

## 对话链接的地址面板

模型正文里的链接，可见文字常常和它指向的地方毫无关系：标题写「季度报告」，`href` 是一百多个字符的查询串。宿主没有给插件留出 markdown 渲染与正文之间的插槽，所以面板从文档层面挂上去，并且完全不碰那个 `<a>`：点击仍然由宿主决定怎么打开，这一面只读地址。

鼠标停在链接上（或键盘焦点进入链接）就出面板，里面是 `href` 原文，右侧一个复制按钮。地址用 `overflow-wrap: anywhere` 换行，宽度上限 `min(480px, calc(100vw - 24px))`，全文可见、不截断：一条三百字符的追踪链接正是这个面板存在的理由，省略号会让它失去意义。

范围只认对话区：锚点的祖先必须命中 `[data-slot="conversation.chat.flow"]`（模型正文）或 `[data-message-bubble]`（用户气泡，宿主今天不往里面渲链接，但真渲了就该是同一个面）。侧栏、设置、工作台、输入框都不算。空白 `href`、`#` 锚点、`javascript:` 与 `data:` 不出面板；`mailto:`、相对路径、其余协议照常显示，因为面板描述链接而不是替宿主判断点击语义。

定位是纯函数：优先放链接下方，下方放不下就翻到上方，两侧夹进视口并留 8px。面板 `position: fixed` 挂在 `document.body`，滚动就关（它自己的滚动除外），因为固定定位不会跟着链接走，留着就会指着一个已经滚走的链接。

复制先走 `navigator.clipboard.writeText`，被拒时退到临时 textarea 加 `document.execCommand("copy")`。成功后按钮文案变成「已复制」，两路都失败变成「复制失败」，1200ms 后回到「复制」。按钮的 click 阻止默认行为与冒泡。

关闭条件：指针离开链接且离开面板、链接失焦且焦点不在面板内、Escape、窗口滚动。链接和面板之间有 8px 空隙，空隙属于正文，指针经过时 `mouseout` 的落点不是面板。所以离开链接后先等 300ms 再关，这段时间里进入面板就取消关闭。面板上下各有一条透明的命中垫，盖住这 8px，指针不用穿过死区。否则复制按钮永远够不着。`(hover: none)` 的设备整个不挂面板，`prefers-reduced-motion: reduce` 时不做位移与淡入。颜色全部走宿主 `--dsw-alias-*` token，与技能面板同一套，亮暗主题自动跟随。样式表落在自己的 `#dsh-better-link-hover` 标签里，热重载再挂不会插第二份。

## 技能别名

设置里多一个「技能别名」页（`settings.section`，id `aliases`，排在 Tab 管理与工作台之间），把短词映射到带参数的斜杠调用，例如 `wf` → `/flow-workflow run`。页面只有两个区：上面一个开关决定关键词是否必须带前导斜杠，下面一张表填关键词、技能或命令、参数；每行即时写入，没有保存按钮。

规则只有一条但两侧必须一致：关键词在草稿最前面、且后面要么是结尾要么是空白时才算命中，大小写不敏感；空关键词或空目标的半成品行只是草稿，匹配时跳过。同一个关键词可以写多行，面板会把它们当作同一组候选。

触发面分两种模式，共享同一个原生菜单：

- 前缀开启（默认）：本包往宿主 `ctx.inputTriggers` 注册一个 `/` 源，名字 `alias`，排在原生 `command` 组之前。输入 `/` 时「技能别名」组和宿主的「技能」组并排出现，输入 `/wf` 后收窄到别名行；按空格后原生菜单本来会关闭，watcher 会用同一段草稿重开该组并把替换 span 扩到空格之后，所以 `/wf ` 仍然停在面板上。选择行插入 `/flow-workflow run `。
- 前缀关闭：输入 `wf`（无需斜杠）时，`conversation.input.overlay` 里一个渲染 null 的 watcher 读 `conversation.input` 的会话草稿，调用同一个 `InputTriggerController.toggleSource` 打开只含别名组的菜单；输入空格后重新开一次以更新 span。草稿一旦不再等于某个关键词就关闭自己开的菜单，不会在写正常句子时乱弹。

面板没有自绘：`alias-source.ts` 只提供 `candidates` 与 `onPick`，菜单本体、分组标题、键盘（↑/↓、Enter、Tab、Escape）、指针悬停与选择、`aria-activedescendant` 全是宿主 `MenuView` 的实现；这也是「操作完全仿照原生技能面板」的落地方式。`alias-watcher.tsx` 只做「什么时候打开」，不做任何菜单渲染。别名选择只插入文本，不自动提交，和原生技能面板的行为一致。

选择行先插入 `/目标 参数 `。如果目标命中宿主已注册的命令（比如 `td` → `/placeholder`），插入后会把命令 token 交回同一个触发器流水线，由宿主的 command source 认领成真正的命令芯片，参数作为命令参数提交；不是命令的 skill 目标保持普通文本。这样 `td` 不会变成一条字面量 `/placeholder` 消息。

配置存在 `localStorage` 的 `dsh-better.skill-aliases`，形如 `{"v":1,"prefix":true,"rows":[{"id":"…","keyword":"wf","target":"flow-workflow","params":"run"}]}`。坏文档当成空配置，坏行按类型丢弃，读取不会因为一条损坏记录丢掉整张表。

## 技能增强

从斜杠菜单选中技能后，输入框里那个 `/flow-workflow` 会带上两样东西：它后面浮现的灰色参数提示，以及鼠标停在它上面时弹出的详情面板。

灰字取该技能 `SKILL.md` frontmatter 里的 `argument-hint`，也就是技能作者写给人看的那串参数说明。它只在「草稿以这个技能 token 开头、且 token 之后只剩空白」时出现；键入任何非空格字符立即消失，删回只剩空格又回来。它不占用宿主的 `--dsh-composer-hint` 变量——那条通路只在命令被认领（claim）后由宿主写入，而技能是纯文本 token，够不着，本包改为在编辑器之外自绘一层。代价是光标位置拿不到精确值（宿主的输入状态不发布 caret），判据用「草稿尾部是否只剩空白」近似，把光标移回 token 内部但不改文本时灰字会残留到下一次击键。

详情面板列出七项：技能名、技能描述（frontmatter 的 `description`）、frontmatter 的 `metadata:` 块逐项、`SKILL.md` 的绝对路径、本会话调用次数、本工作区调用次数，以及从 `argument-hint` 解析出的参数列表。参数是可点的：点一下就把该参数追加到光标处并补一个空格，面板不关、焦点不回编辑器，所以可以连着点几个。参数只插入 flag 本身，`<a|b>` 这类值是提示不是草稿内容。

面板宽度按描述长度分三档自适应，不是定值：无描述 240px、描述不超过 80 字 320px、80 到 200 字之间 480px、200 字及以上 640px（也是上限）。分档而不是连续取值，是因为相邻两个技能不该因为差几个字就弹出宽度不同的面板。档位来自本机 180 个技能的实测分布：描述中位数 175 字、81 个超过 200 字、最长 895 字；200 字在 640px 宽下约排 4 行，再宽就开始盖住它悬浮其上的对话内容，收益抵不过代价。所以超过四行的部分在样式层被 `line-clamp` 截断，完整描述挂在元素的 `title` 上，鼠标停留可见。宽度还要与视口协商：`min(640px, 100vw - 24px)` 保证窄窗口里不溢出，算出宽度后左边缘再做一次钳制，否则靠近窗口右边界的技能 token 会把大半面板推出屏幕。

参数解析面对的是真实 world 的脏输入：方括号可嵌套（`[--create [--scope <a|b>]]`）、`|` 在尖括号内是值枚举而在外是互斥分隔、`·` 也被作者用来分组、尖括号占位符里可以有空格（`<URL or browser task>`）。解析成平铺的 `{flag, detail}` 列表，任何输入都不抛错——完全无法结构化时整段作为一条，保证面板不为空。

三样数据各有来源，不能混：

- **参数提示与元数据**：宿主 `ctx.skills.get()` 拿到的 `metadata` 只含 `metadata:` 嵌套块，顶层 `argument-hint` 被 frontmatter 解析器丢弃，任何宿主 API 都取不到。所以本包宿主半新增只读路由 `GET /better/api/skill-profile?sessionId=&name=`，按 `path` 重读一次 `SKILL.md` 取那个键。
- **本会话调用次数**：宿主半注册 `skillUsage` 投影，折叠会话日志里 `user/message` 且 `source.kind === 'skill-invocation'` 的事件。这类事件是宿主在用户显式调用技能时注入的，name 字段就是权威技能名。fork 出来的会话带祖先前缀，按 `fromSeq` 跳过（与 `sessionCompaction` 同一套判据）。
- **本工作区调用次数**：客户端从 `sessions.list` 快照里按 `byId[id].cwd` 严格相等筛出同工作区会话，把各自 `projectionsBySession[id].values.skillUsage.counts[name]` 求和。纯内存读，零 IO。它只覆盖宿主已加载投影的会话，所以刚打开的旧会话可能短暂低估，随投影加载自行收敛。

「总次数」按本工作区解释，不是整机全局：跨工作区总计需要枚举全部会话日志并逐个解析，实测规模是每会话一次完整读取，在悬浮面板这个交互里付不起。面板因此只显示两个数字，不显示一个看起来像全局的假数字。

三处降级都是有意的：宿主没有 `webServer` 时路由不挂载，面板只显示名称与路径；`skills` 远程不可用时拿不到技能集合，灰字与面板都不出现，本包其余能力不受影响；`sessions.list` 形状不符时退化为只显示本会话数字。降级一律静默、不抛错，因为这条链路跑在输入框的渲染路径上。

命令不参与增强：`/placeholder` 这类命令有自己的 claim 提示与参数弹窗，宿主已经做了，重复实现只会两边打架。增强只对技能生效。

### 参数候选面板

技能 token 之后输入 `--` 会直接弹出参数候选面板，不需要先把鼠标停上去。面板锚在光标附近：优先读当前 selection 的 caret 位置，拿不到就退回编辑器文本节点的矩形，两者都拿不到就不渲染——宿主的输入状态不发布 caret，与其猜一个位置，不如不画。

候选随输入实时收窄，`--s` 只剩 `--search`、`--simplify` 这类前缀命中的 flag，裸 `--` 列出该技能所有能补全成 flag 的参数。只有草稿末尾正在输入的那个 token 参与过滤，已经写完的参数不参与，所以回头改前面的参数不会让列表跳走。位置参数（`<file>` 这种）不进候选：这个手势补的是 flag，一个补不成 flag 的行只会让人点了没反应。

点击候选把正在输入的 token 整体替换成完整 flag 并补一个尾空格，是一次独立的可撤销编辑；前面的技能 token 与已经写好的参数原样保留。重复参数不设限，已经出现过的 flag 不会被排除，要不要再来一次由用户判断。面板不抢焦点，Escape 与点击面板外都能关掉，关掉之后继续输入会重新打开。

两个面板有明确分工：参数面板打开期间悬浮面板让位，免得两个浮层抢同一块位置；在悬浮面板里点参数是追加到草稿末尾，在参数面板里点候选是替换正在输入的 token。参数面板不接管方向键、Enter 与 Tab，提交与菜单语义仍然归宿主；它只做前缀过滤，不补参数值，`<a|b>` 这类值始终只是提示。

### 目录面板

参数候选只能列出 flag。值本身是一份目录时（工作流 slug、以后还可能是别的清单），技能在自己的 `SKILL.md` 里声明哪个词由目录填充：

```yaml
metadata:
  assist:
    - slot: run
      kind: catalog
      title: 工作流
      source: workflows
```

`slot` 是草稿里那个完整词，`kind` 目前只认 `catalog`，`source` 目前只认 `workflows`，`title` 可省，省了就用 slot 本身当标题。缺字段、认不出的 kind 或 source 整条丢掉，同一个 slot 只留第一条。这一列表不进悬浮面板那张已经拍平的 metadata 表，两边各看各的。

`workflows` 源读三处清单，同名 slug 先出现的赢：会话工作区的 `.claude/workflows/index.md`、`.agents/workflows/index.md`，再加 `~/.data/flow-workflow/index.md`。行要以列表符号开头，slug 是行首的 kebab token，冒号后是一句话目标。读不到的文件跳过。没有这条声明就不读盘。

打开条件看的是 token 而不是前缀：草稿以该技能开头，slot 词本身是一个完整 token，而且它就是值前面那一个 token。`/flow-workflow run` 后面还没有空格时不打开；空格打出去才列出全部，`run dev` 按 slug 或目标筛选。slug 前缀命中排在 slug 包含之前，目标里的命中排最后，同一档保持清单原顺序。命中片段高亮，原文大小写保留。值写完再跟别的 token 就关闭。`--dynamic run ` 仍然打开，因为 `run` 依然是完整的 slot 词。末尾正在输 `--` 时让给参数面板。

点击或回车把正在输入的值替换成 slug 加一个尾空格，不写目标文本。目录面板打开时接管上下键与回车，不接管 Tab；输入法正在组字时回车仍归输入法。Escape 关闭，草稿再变就重开。

## 开发

```sh
pnpm --filter dsh-better test       # 纯逻辑单测
pnpm --filter dsh-better typecheck
pnpm --filter dsh-better build      # 产出 lib/
```

`src/client/search.ts` 是纯排序逻辑（无 DOM、无 React），`groups.ts` 复刻原生分组与 per-group 排序，`overlay.tsx` 负责渲染与遮蔽，`focus.ts` 是快捷键的声明、解析器与两条宿主探测（当前会话、输入框是否在屏）。`alias-store.ts` 是别名的文档编解码、增删改与两套草稿匹配（无 DOM、无 React），`alias-source.ts` 只生产原生菜单的候选与插入文本，`alias-watcher.tsx` 只决定何时用 `toggleSource` 打开它，`alias-page.tsx` 是设置页。`test/focus.test.ts` 把宿主的命令 id 规则、web 可接受组合与解析器的三种让位情形钉成断言——注册被宿主拒绝时命令会从面板里消失且不报错，这种失败只能靠断言挡住。

`composer-clipboard.ts` 是剪贴板契约（编码、解码、纯文本拼装、路径列表解析、按路径去重），无 DOM 无 React，`test/composer-clipboard.test.ts` 钉住三件事：同应用往返无损、纯文本那份能单独用、文本解析足够窄（提到路径的句子不会被吞成附件）。`composer-attachments.tsx` 是附件栏的包装组件与 DOM 事件面，行为靠真机验证——全选标记、复制写入、粘贴还原、去重、清除时机。

`src/compaction.ts` 是 `sessionCompaction` 投影单元（折叠、schema、wire view），`src/index.ts` 只做注册；`test/compaction.test.ts` 把口径钉死：`compaction/end` 无 error 记落地、带 error 记失败、`start` 与 `summary` 都不计、`seq` 小于继承前缀的事件整段跳过；另外还断言无关事件返回同一个引用（每个 token chunk 都会过这个折叠，换新对象会让 registry 的 `Object.is` 变更检查每次都触发）。`client/compaction-stat.tsx` 的 `compactionReading` 是纯函数（零次静默、单复数、失败说明），`client/compaction-styles.ts` 的样式规则由 `test/compaction-stat.test.ts` 断言 `order: 1` 与 slot 顺序的配对——这两半必须一起成立才能落在占用环右边。

`client/layout-widths.ts` 是面板宽度记忆的纯决策（文档编解码、computed grid 列解析、一次拖拽该记哪根栏、恢复计划），`test/layout-widths.test.ts` 钉住四件事：坏文档只丢坏字段、折叠栏不写成 0、拖左栏不会把右栏被挤压的让步值记进去、宿主没有那组私有 action 时恢复静默降级。`client/layout-adapter.ts` 是宿主接线（读私有 bound action、找 frame、监听原生 pointer 序列），行为靠真机验证：两栏拖宽后刷新页面与服务重启都保留。

## 会话标签栏

插件往 `conversation.view` 注册一条，标签栏就多一个标签：WakaTime、文件、Git、轨迹都是这么来的。宿主自己只有一个隐藏手段，就是头部「更多」菜单里的取消固定，而且那份名单只活在内存里，刷新即丢，这个菜单在当前宿主上又不会出现。于是标签一旦注册，就没有地方把它关掉。

设置里因此多一个「Tab 管理」页（`settings.section`，id `tabs`，排在工作台前面）。第一行是固定的 1 号位「对话」：没有勾选框、也不能拖——宿主把它写成固定项，永远在最前，也是其余标签都关掉之后的去处，给它一个控件等于放一个不会生效的东西；行右有一段灰字说明（「固定在标签栏最前，不可隐藏或拖动」），这是页面上唯一一处解释性文字，没有它，一行没有控件的行读起来像坏了。之后每个已注册的标签一行，行首是它在标签栏里的序号，勾选即显示，取消即从标签栏拿掉。行可拖拽排序：拖过某行中线就实时让位，松手才把整份顺序一次写给控制器；没松手的拖拽在 dragend 时按存储顺序重绘回来。序号是「显示中的标签」的位次——对话是 1，后面每个勾选中的标签依次 2、3、4；隐藏的行没有序号，它不在条里，没有位次可占。

关掉一个标签只拿掉它的标签，不碰它的注册，也不碰当前正在看的内容。内容区渲染的是会话记住的视图 id，跟这个 id 还有没有标签无关；把注册撤掉会让打开中的视图直接空白，数据源也一起没了。所以隐藏走的是样式表：本包在文档上挂一张 sheet，对 `[data-conversation-tabs]` 里的第 N 个 `button[role=tab]` 写 `display: none`。勾回来只是把规则撤掉，不会因此跳进那个视图。

不走宿主的 pin seam 是验证过的死路，不是偷懒：`conversation.session.header` 是宿主自占的 `single` slot，目录里 `registerOptions: []`，pin 状态（`viewPins`）是这个包里的闭包，唯一出口就是那个 slot 的 inject props。第二个注册与占用者同优先级会当场抛错（第一版就是这么把 web boot 打挂的），优先级更低会赢得 cell 把整个头部换成空渲染，更高则永远不挂载、inject 永远不跑。样式表是宿主不参与也不拦的通道，语义等价：标签不见、视图保留、宿主重渲染按钮也不影响规则。

规划规则前先读一遍标签条的真实 DOM：位置模型要求「按钮数 = 对话 + ledger 行数、每个标签文本与 ledger 解析出的 label 逐位相等」，全对上才按位寻址（对话占第 1 格，ledger 第 i 行占第 i+2 格）；宿主按开发者工具开关会滤掉轨迹标签，位对不上时退化为按 label 文本在按钮里找唯一匹配，找不到或有歧义就一个都不藏——藏错邻居比不藏更糟。宿主还没渲染头部时（本包 apply 早于 React 挂载）按帧重试而不是瞎猜。规则在 ledger 变动与勾选切换时重排，所以后注册的插件插入中间也会让后续按钮跟着挪。

排序落在同一条标签条上：它本来就是个 flex 行，按钮的位次就是 `order` 值，本包给每个按 label 认得出的按钮写内联 `style.order`（对话永远不碰，占默认的 0 继续领跑），勾掉一个标签，序号就地收紧，勾回来照文档里的位置归位。宿主重渲染按钮会把内联样式连同隐藏标记一起冲掉，补盖的是同一个 MutationObserver。寻址的守卫比隐藏更严：一个标签若对不上唯一按钮——两个视图同名，或某个视图与对话同名（对话是条里第一个按钮，label 相同就分不出谁是谁）——整个重排就放弃，半截挪动比不挪更糟。这个内联 order 同时是工作台数字键的寻址依据：`dsh-workbench-core` 的 `listViewTabs` 照它排序，`⌘2` 打开的永远是你看到的 2 号位，重排前后一个语义。

选择存在 `localStorage` 的 `dsh-better.tabs` 里，当前形如 `{"version":2,"hidden":[],"order":[]}`（旧版是一份裸数组，照读等价于只有 hidden），跟宿主按会话存的草稿文档分开。坏掉或读不出的文档当成「什么都不记」，避免一次损坏把所有标签藏掉。`order` 只是被记住的顺序：记得的排前面，没记得的按宿主次序跟在后面；已卸载插件的 id 留在文档里不删，插件回来了槽位还在。名单是唯一事实：样式表与内联 order 每次加载都照它重排，宿主自己的取消固定名单既然没有入口可写，也就不存在要迁就的并发改动。

## 面板宽度记忆

宿主的布局 store 是内存态：每次加载左栏从 280px、右栏从「空」重建，右栏第一次展开才按窗口宽度的 45% 定下宽度。于是拖好的宽度一重启就没了，左栏跳回 280，右栏跳回大半个窗口。这不是 bug，宿主文档里明写了「面板几何是暂态的，刷新恢复默认」，持久化只能落在外部。

本包维护一份全局文档 `localStorage` 的 `dsh-better.layout-widths`，形如 `{"sidebar":390,"rightbar":700}`，两根栏各一项。两份宽度都是整窗偏好而不是会话事实，所以是全局一份；右侧栏自己的布局（标签树、选中、展开态）仍由 `dsh.sidebar-right.v1.<sessionId>` 按会话保存，本包不碰。没拖过的栏不写进文档，空文档等于「什么都不恢复」，新装用户看到的仍是宿主默认几何。

恢复走 layout store 自己的 action，不是覆盖 grid：`ctx.layout` 公开面只有导航（`selectPanel`、`toggleSidebar`、`openRightbar`、`closeRightbar`），宽度写入在根 store 的 bound action 集合里，只在服务实例的 `panels` 字段上可达。那是私有字段，包内按运行时特性检测使用，宿主改名或删掉就静默降级为「不恢复」。走 action 的收益是三方一致：store、frame 的 inline `grid-template-columns`、拖拽手柄说的永远是同一个数；如果改成注入一张 `!important` 样式表盖上 grid，宿主下一次拖拽就会与覆盖层打架，用户拖不动、store 与视觉还会分叉。

写入时机是拖拽结束时，监听的是浏览器原生的 pointer 序列而不是 frame 的 `data-dragging`。那个属性是 React 状态投影，快拖有可能在一次 commit 里起止，属性从未变过，宽度就永远记不下来。手柄自己捕获指针，所以松手事件一定拿得到，`data-side` 还顺带说明了拖的是哪根栏。松开后等一帧再量：store 的写入在宿主自己的 pointerup 里，frame 的 inline grid 要等那次 commit 落地。拖左栏时右栏会被挤窄，但那是 frame 算出来的让步、不是右栏的偏好，按 `data-side` 结算就不会把挤压值写进右栏记忆。

不记忆的边界：折叠态归宿主（左栏折叠即忘记宽度，展开回默认宽度，这是宿主的产品决定，本包不改）；窗口变窄时 store 的 clamp 与 frame 的让步照常生效，记忆值只在宿主允许的范围内落地。桌面端与 web 端是两个 origin，各自记忆各自的宽度。

## 右侧栏外扩（桌面端）

右侧栏的宽度是从中列里扣的：面板一开，正文整块左移、左右留白塌缩。桌面端的窗口有自己的几何，所以这里换一种付账方式——窗口从 W 变 W + 面板宽，中列逐像素不变，正文不动。

接缝是 `ctx.layout.openRightbar(track, fullscreen)` 与 `closeRightbar()`。宿主的右侧栏座位每次呈现变化都经这一对方法上报，包装实例方法就能拿到与面板完全一致的时机，不需要轮询布局 store 或观察 DOM。每次调用先原样交给宿主，再决定要不要动窗口：宿主对面板的所有权不被这段代码改写，窗口只是事后追加的一次调用。

加宽量取面板的渲染宽度而不是 store 里的偏好值——偏好是期望值，中列丢掉的是 clamp 之后实际用掉的宽度。面板选择器优先 `[data-sidebar-right-session]:not([hidden])` 包裹的那一个：后台保留会话的面板也留在 DOM 里按会话 id 排序，裸属性可能量到隐藏面板的 0 宽。

四条否决，任一成立就不动作、退回宿主的推挤：不是桌面端（`dshDesktop.protocolVersion === 1` 是外壳唯一的自我介绍，浏览器里没有这个全局）；不是普通呈现（面板全屏或窗口全屏，全屏里改窗口尺寸没有意义）；屏幕右侧的余量装不下面板宽（不移动窗口去凑）；面板宽为 0（还没渲染出来）。关闭时只撤销自己加的那一份：窗口仍停在 `base + added`（±2px）才缩回 `base`，用户中途改过窗口就只清账、不动它。

偏好是 `localStorage` 的 `dsh-better.panel-grow`，`{ "expandWindow": true }`，默认开。设置页「布局」里的开关改写它，运行时每次开合现读，点完下一次开面板就生效，不用重载。

边界：`window.resizeTo` 是渲染层的 DOM 接口，不是 Electron 的契约。它在 44.7.0（本机桌面壳的 Electron 大版本）上实测生效——800×600 的最小窗口被页面改成 1100×700，左上角不动；若未来大版本收紧，表现是静默不动作，宿主布局不受影响。真机验收：桌面端打开右侧栏应看到窗口右缘外移、正文位置不变；关闭后窗口回到原宽度；把窗口拖到屏幕右缘再打开应保持原样（余量不足）。

## 弹窗实色

设置弹层、技能悬浮面板、参数候选与链接悬浮卡的面板底色都来自 `--dsw-alias-bg-layer-2`。装了 ascii-rest 皮肤时，这个 token 被皮肤按场景底色调成带 alpha 的半透明色——面板因此透出底下的对话与终端，整页看起来像坏了：弹窗里的内容没有一处是故意要与背后对齐的。这些面板只做一件事：把背景重新声明成同一个颜色去掉 alpha。色相仍由 token 单独决定，亮暗主题与换场景都自动跟随；宿主自己的 token 本来就是不透明的，这条声明落上去等于原样。写法是 CSS 相对色（`rgb(from var(...) r g b / 1)`），不支持的引擎丢弃第二行声明，保留第一行原样，退化为无操作而不是画错颜色。

设置弹层的接缝是宿主自己的 `[data-shortcut-modal="settings"]`，不是 CSS module 的哈希类名——后者每次构建都变，前者是宿主快捷键路由已在用的稳定拼法。一张按 id 幂等的 sheet 就够了：弹层在本包 apply 之后很久才挂载，样式表挂在那里等它。本包自己的三个浮层把这条声明写在自己的规则里（`skill-styles.ts` 与 `link-hover-styles.ts`），与它们各自的 token 选择放在一起。

技能别名旁边的工作流目录面板是唯一的例外：它刻意用斜杠菜单的 `--dsw-specific-menu` 与背景模糊，因为那两块钱同时出现，换一种材质会读成第二张卡。
