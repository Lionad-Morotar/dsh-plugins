# dsh-git-explorer

会话工作目录的 Git 面板：左边是工作区变更，右边是提交图和选中提交的详情。宿主半承担取数与解析，浏览器半边只做两栏视图；它以 `conversation.view` 的「Git」标签出现，排在「文件」之后，会话顶栏另有一个分支切换器，切换作用在会话工作树上。

## 安装

```jsonc
// ~/.dsh/profiles/web/package.json
{
  "dependencies": {
    "dsh-workbench-core": "link:<checkout>/packages/dsh-workbench-core",
    "dsh-git-explorer": "link:<checkout>/packages/dsh-git-explorer"
  },
  "dsh": { "profile": { "bundles": ["…", "dsh-workbench-core", "dsh-git-explorer"] } }
}
```

```yaml
# ~/.dsh/profiles/web/cordis.patch.yml
- insert:
    - id: core
      name: 'dsh-workbench-core'
    - id: git-explorer
      name: 'dsh-git-explorer'
```

`dsh plugin --profile web install` 后重启宿主；desktop 用插件管理器装同一个 `link:` 路径。本包有宿主半边，Loader 行必须在宿主侧解析成功；客户端半边另需核心包的 `workbench` 服务。`lib/` 是提交入库的产物，安装态不跑构建。

## 核心能力

- 宿主服务 `GitExplorerService`：Typert Remote 服务，服务名与线命名空间都是 `gitExplorer`，向客户端暴露 `snapshot` / `query` / `commit` / `show` / `branches` / `switchBranch` / `run` 七个端点。`branches` 是只读的分支清单，`switchBranch` 是唯一的写端点；`show` 按 `<hash>:<path>` 只读读取某个提交版本的单文件内容页；`run` 仍是类型化占位，当前一律回 `not-implemented`。
- 客户端传输走连接服务的原生 RPC：`ctx.get("connection").rpc.call(rpc, "/api", "gitExplorer/<method>", { args: { request } }, signal)`，返回值是 `{ ok, value }` 传输封套。之所以不用 `ctx.remote.gitExplorer`：那个类型化命名空间只存在于「用 `ctx.remote.$mount()` 挂载了生成贡献物」的包里，第三方包没有生成物；宿主侧的 `typertRemote` 绑定会被网关的 source-mode 发现枚举，路由 `/api/gitExplorer/<method>` 因此开箱可用。
- 只走 argv：所有 git 调用都是数组，从 `git` 开始，不拼 shell；每条命令 20s 超时、4MB 输出预算，超出走 spill 回读，stdout 有损时明确失败而不是交出半页数据。
- 仓库快照：仓库根、当前分支与 HEAD（含游离 HEAD、领先 / 落后）、按 hash 分组的引用、工作区变更、逐文件增删行数、首页提交与泳道、原始 `git status --porcelain=v2 -z` 文本（供文件树着色复用）。快照还带 `remotes`：`git remote -v` 的远端清单，每个名字一条、按名字字典序，同时有 fetch 与 push 时取 fetch URL，只有 push 时用 push URL；URL 原样保留不做归一化（归一化与 provider 识别在客户端），所以 `git@host:owner/repo.git` 与 `https://host/owner/repo` 在这里是两个不同的字符串。
- 提交查询：`git log --topo-order --parents`，多取一条判断 `hasMore` 后丢掉。查询端点支持 `skip` / `limit`、`--grep` 与 `--author`（面板本身只用分页）；ref 只接受分支、标签或提交名，带修订语法或 `..` 的一律拒绝。
- 泳道布局：单次扫描加最小堆复用泳道，线性历史同泳道、分叉换道、同层不撞道；父提交不在本页时只留悬空边，不占道。3000 commit 的解析与泳道分配在本机是 5ms 量级，判据门槛是 300ms。
- 两栏视图：左侧变更按目录分组，状态字母（A/M/D/R/C/T/U/!）加每文件 `+n −n`；点非目录文件会跳到文件面板并打开对应行。右侧提交图只渲染视口内的行，选中提交在下方展开父提交、说明与变更文件清单。
- 历史栏是分栏表格，列序固定为 Graph | Refs | Description | Date | Author | Commit。refs chips 独立成列，位置在 graph 与提交描述之间：分支名长短差异很大（`origin/codex/feature/fullstack-migration-design`），只有独立成列才拖得宽也截得断，挤在描述前会把描述推到右边。短哈希从第二列移到最后一列，它是查证用的次要信息，占第二列会把描述挤开。表头常驻在滚动容器外面，滚动列表时列标签与拖拽手柄不会滚走。
- 四列可拖宽：refs / 日期 / 作者 / 提交各在表头右缘有一个 `role="separator"` 手柄，指针拖拽加键盘同构（`←`/`→` 微调 16px、`Home`/`End` 到该列最小 / 最大、双击或 `Delete` / `Backspace` 复位）。描述列是 `minmax(140px, 1fr)` 吸收剩余宽度，graph 列宽由泳道数算出（36–116px，最小宽度受表头列名约束：单泳道只要求 12px，那样 10px 字号的 `Graph` 会被截成 `Gr…`，所以地板取列名加左右各 4px 余量），两者都不提供手柄。列宽写 `localStorage` 的单键 `git-explorer.historyColumns`，值是稀疏 JSON：只写与缺省不同的列，所以缺省调整后没被拖过的列会自动跟随新缺省。一份宽度对所有会话、所有仓库生效。读取时键缺失、JSON 损坏、顶层不是对象、某列非有限数或越界，都只让那一列回落缺省而不做夹取，因为旧规则写下的数不是今天的意图；其它列不受牵连。
- 未提交变更行：工作区脏时历史列表首行是「未提交的变更 (N)」，与提交行同高并共用同一套 grid 模板。graph 列画空心圆环（`fill: none`，描边走 accent），与下方实心提交点在读文字前就能区分；日期列显示 `+A −D` 合计，只有未跟踪路径时留空而不是报 `+0 -0`；引用、作者、提交三列留空。它是键盘光标停靠点，`Home` 脏时落在这里，移动光标即选中。选中它时右栏换成工作区摘要：标题、文件数与总 `+A −D`，正文按目录分组列出变更文件，行是原生按钮、点击打开文件。数据全部来自内存快照，不发新请求，也不改 `commit` 端点。工作区干净时该行不出现，也不留空行占位。
- 两条分隔条：左栏与右栏之间是竖向分隔条（调宽度），历史列表与提交详情之间是横向分隔条（调高度），两者交互同构：指针拖拽、方向键微调、双击或 `Delete` 恢复默认。竖向用 `←`/`→`、`Home`/`End` 分别对应最小与最大宽度，横向用 `↑`/`↓`、`Home`/`End` 分别对应最高与最低高度（手柄在详情上方，`Home` 落在轴起点即详情最高的位置）。两者都只声明 `aria-*` 与 `title`，键位不向宿主的快捷键目录注册。历史列宽手柄是第三套同类交互，键位语义与竖向分隔条一致。
- 详情高度的存储口径：存的是右栏高度的百分比而非像素，所以在高屏上拖出的分割换到矮窗仍然是同一个比例，不会变成一个矮窗才合理的固定值。默认不写存储，交给样式表的 `38%`；拖动落回原位则不写入（与宽度一致，见 `dragReturnedToBase`）。像素夹取在 `detail-height.ts`：下界是详情自身的 `180px` 地板，上界给上方历史列表留 `120px`，因此拖到顶也吃不掉列表；`Home`/`End` 落点走同一套像素夹取再换算成百分比，避免存下一个样式框根本不采用的比例。列高测不到时（隐藏挂载、jsdom）用 `FALLBACK_COLUMN_HEIGHT` 兜底，键盘不至于静默失效。
- 行光标（变更与历史两栏共用一套语义）：滚动容器可聚焦，`↑` / `↓` 在渲染出来的行上移动光标，`Home` / `End` 到首尾，`Enter` 在变更栏打开文件、在历史栏选中提交。变更栏的光标把目录头也当成停靠点，它在屏幕上占一行，跳过它会让人觉得漏了一步；`Enter` 落在目录头或目录行上不做事，因为那后面没有可打开的文件。历史栏光标移动即等于点击：详情面板跟着换，不会要求再按一次 `Enter`。历史栏的行集合在工作区脏时是「未提交行 + 提交」，光标索引基于这个集合，所以 `Home` 脏时落到未提交行；靠近末尾自动取下一页的判据仍按提交数计算，合成行既不提前触发也不压住它。
- 最小位移跟随：光标已完整可见时不动滚动位置，越出视口才移动刚好够用的距离（不是居中）。历史栏是虚拟列表，跟随因此需要「按行下标反求 `scrollTop`」的反向计算，它与 `computeWindow` 共用同一个行高常量 `HISTORY_ROW_HEIGHT`；两处各写一个数字的话，每次移动都会差一行。变更栏的目录头与文件行高度不同，跟随交给浏览器量出来的 `scrollIntoView({ block: "nearest" })`。
- 光标与选中是两件事：`data-cursor` 只是键盘落点，`data-selected` 是被选中的提交。历史栏里移动光标会顺带改变选中（等同于点击），但点击或跨面板跳转也会改选中，此时光标跟着过去，让第一次方向键从读者正看的地方继续。光标接近已加载末尾时自动取下一页，取完继续走。
- 变更栏过滤：面板头的输入框按路径子串过滤，大小写不敏感；匹配范围是完整仓库路径，因此目录名天然也匹配。过滤只减行不重组：目录分组是「这个文件在哪里」的答案，重组会把问题换成另一个。命中为空给专门文案；被过滤掉的光标会落到附近的可见行，不会留在隐藏行上等一个指向空气的 `Enter`。
- 历史栏搜索：面板头的输入框按提交信息搜整个仓库历史（宿主 `git log -F --grep`），结果整页替换列表，泳道图随新页重排；清空查询直接还原视图已持有的快照页，不再请求一次。搜索态下分页带着同一个查询继续取，否则「本页没有、下页才有」时会出假空态。输入 250ms 防抖，因为每次搜索都是一个 `git log` 进程，逐字母发请求不划算。`-F` 让查询按字面文本匹配：搜索框不是正则编辑器，读者打 `[` 或 `(.` 时想找的就是这些字符，而当模式解释时它们要么是另一个查询，要么直接 fatal。只在已加载页里过滤被明确排除：那是另一个功能，会给错答案。
- 提交详情文件行：悬浮 200 毫秒后显示该提交版本的轻量预览卡，移出、滚动或 `Esc` 收起；点击打开文件工作台的面板，内容同样来自该提交，标签带短哈希。删除的文件读第一父版本并在卡片与面板标注；重命名按新路径读取，标题用新路径；子模块显示对象 id 并明确不可预览；二进制与超限各有状态，不渲染半份正文。
- 进入视图时的焦点：从标签栏点进 Git 面板，键盘焦点落在左侧变更列表的第一个文件行（目录行只做分组，跳过）。这次认领只在视图挂载后的第一份快照渲染时兑现一次，快照刷新不会重来；焦点已经落在变更区内、或列表里没有文件行时不动，免得把读者从已选的行上拽走。显式的 `commit:<hash>` 跳转优先，此时不抢焦点。
- 焦点跳转：接受 `openView("git-explorer", "commit:<hash>")`（hash 为 4-64 位十六进制，大小写归一为小写），命令面板输入提交前缀跳转即按此协议寻址。焦点有两个来源：宿主经 `openView` 交下来的 `viewRequest`，以及 `workbench.viewFocus` 队列（视图已挂载时命令面板走的通道，挂载时取走等待中的请求并持续订阅）。命中即选中该提交，详情面板按 hash 经 `commit` 端点独立加载，hash 不在已加载列表也能展示；历史列表不插行以保住拓扑泳道序。解析失败也回执完成，宿主才会清掉这条请求。
- 顶栏分支切换器：会话顶栏 action 行的分支触发器显示当前分支（游离 HEAD 显示短 hash），点开是本地分支浮层。图标、面板与配色都自带（`--dsw-alias-*` 语义 token），不借宿主的 action 类名，那些类名带构建哈希，每次宿主构建都会变。
- 工作区判脏读数：分支名后紧跟 `+128 −34`（`+` 走 success 语义色、`−` 走 error 语义色，11px 表格数字），为零的一侧省略；两数皆零但工作区脏（只加了未跟踪文件、或只发生 rename）时显示 `•`，干净时不出任何数字。触发器 `title` 是工作区描述「工作区 +128 −34，3 个文件变更，1 个未跟踪文件」，干净时为「工作区干净」；`aria-label` 是「切换分支: main，工作区 +128 −34」。分支名过长先截断名字（名字自身另有完整 `title`），读数与 chevron 保留；整个触发器 `max-width: min(320px, 40vw)`。
- 浮层作用域：顶部一行 `gx-branch-scope` 说明切换作用在这个工作树上，显示仓库或工作树名，父路径先被截断，`title` 是完整绝对路径。linked worktree 的根路径本身就带 `.claude/worktrees/<name>` 或 `.agents/worktrees/<name>`，直接显示，不做额外探测。非仓库会话整个触发器不渲染；游离 HEAD 时作用域行照常显示。
- 分支列举与占用：只列 `refs/heads` 下的本地分支，当前分支带标记；已被另一个工作树检出的分支禁用，`title` 给出占用它的工作树路径。分支名按完整 ref 读取，同名 tag 存在时不会被染成 `heads/<name>`。
- 搜索与键盘：浮层打开即聚焦搜索框，输入按子序列匹配分支名（大小写不敏感），命中片段高亮。`↓` / `↑` 移动光标并跳过被占用的行，停在两端不循环；`Enter` 切换到光标行，输入法组合中的 `Enter` 不算；`Esc` 关闭并把焦点还给触发器，点击浮层外部关闭时只有焦点没有落在别的控件上才回收。切换被拒绝时浮层保持打开，错误行带重试。
- 切换后的刷新闭环：切换成功让共享 store 的 `revision` 自增，Git 面板订阅这个值后复用自身的重新加载路径重取快照，于是历史首行的 refs、工作区变更与 HEAD 一起更新。顶栏同时重读分支清单，脏读数随宿主回报的新工作区状态更新（脏转干净时数字消失）；前端不自行把计数清零，避免与真实工作区短暂不一致。
- 宿主两个分支端点：`branches` 只读，回 `refs/heads` 清单、当前标记、游离 HEAD 的短 hash、每个分支的工作树占用与工作区脏状态（`worktree: { dirty, additions, deletions, trackedFiles, untrackedFiles }`；行数只统计已跟踪路径，未跟踪文件按个数回报）；仓库外返回 `isRepository: false` 而不是错误。`switchBranch` 是唯一写端点，只执行 `git switch --no-guess <分支名>`，不 fetch、不 push、不 reset，也不新建、改名或删除分支。名称先按形状过滤（NUL、空格、`..`、`~`、`^`、`@{`、前导 `-`、尾随 `/`），再拿完整 ref 清单核对，所以 `HEAD~1` 这类修订表达式进不来；`--no-guess` 让只存在于远程跟踪引用的名字不会被悄悄建成新分支。
- 自动 stash：工作区脏时先 `git stash push --include-untracked` 再切换，成功后 `stash pop` 把改动放回，浮层静默关闭；`pop` 冲突时保留 stash 条目并回 `stash: { stashed: true, restored: false, conflict: true, message }`，浮层保持打开，顶部黄色警告写明「改动已保存在 stash，恢复时发生冲突」并附 stderr 摘要，仍可继续选别的分支。切换本身失败时先 `pop` 回滚再报错，浮层沿用错误行，不额外承诺。空操作识别：`stash push` 前后比对栈顶对象 id，没入栈就跳过恢复与回滚，绝不 pop 用户既有条目。
- 提交版本跳转协议：提交详情文件行向文件工作台发 `git:<hash>:<line>:<path>`，行号段必填，路径取剩余全部内容（因此路径可以含冒号）。文件工作台按 `(revision, path)` 建标签，同一路径在不同提交下各占一条标签。宿主缺 `show` 端点时文件行仍可点，悬浮卡降级为“预览不可用”。
- 分页：首屏默认 400 条（Loader 行 `config.maxCommits`），历史列表每点一次"加载更多"取 100 条，单次请求上限 5000。
- 空态与错误态：未选会话、Git 服务不可用、不是 git 仓库、空仓库、读取失败各有文案与重试；头部有刷新按钮。

## 快捷键

| 动作 | 键 | 说明 |
| --- | --- | --- |
| 打开 Git 面板 | `⌘⇧G` | 由核心包注册，desktop 承诺；web 点标签栏「Git」 |
| 刷新快照 | — | 头部 `↻` 按钮；刻意不占全局刷新键 |
| 移动变更栏光标 | `↑` / `↓` / `Home` / `End` | 光标走过目录头与文件行；进入视图时已落在第一个文件行上，方向键从这里继续 |
| 打开光标下的文件 | `Enter` | 只在文件行上生效；目录头与目录行不打开任何东西 |
| 移动历史栏光标 | `↑` / `↓` / `Home` / `End` | 跳过没有行的位置；移动即选中，详情面板跟着换 |
| 选中光标下的提交 | `Enter` | 光标已经选中了它，`Enter` 只是把同一件事说第二遍，供只按 `Enter` 的心智模型使用 |
| 过滤变更 / 搜索提交 | 直接输入 | 各栏面板头的输入框；变更按路径子串，历史按提交信息搜整个仓库 |
| 选择提交 / 跳转文件 | — | 指针操作（提交行、变更行、父提交 chip、提交详情文件行）；文件行是原生按钮，Tab 可达，Enter / Space 与触屏单击同样触发打开 |
| 看完整引用名 | 悬浮 | 历史行上的分支 / 标签 chip 最多显示两个、超出 12ch 截断；悬浮弹出完整名字 |
| 过滤本地分支 | 直接输入 | 浮层打开即聚焦搜索框；子序列匹配，命中片段高亮 |
| 移动分支光标 | `↓` / `↑` | 跳过被其他工作树占用的行，两端不循环 |
| 切换到光标行 | `Enter` | 输入法组合中的 `Enter` 不触发切换 |
| 关闭分支浮层 | `Esc` | 焦点归还分支触发器；外部点击关闭只在焦点没落到别的控件上时回收 |
| 调整左栏宽度 | `←` / `→` / `Home` / `End` | 焦点在左栏分隔条上时生效；`Home` / `End` 到最小 / 最大宽度 |
| 调整详情高度 | `↑` / `↓` / `Home` / `End` | 焦点在行分隔条上时生效；`↑` 让详情变高，`Home` 最高、`End` 最低 |
| 调整历史列宽 | `←` / `→` / `Home` / `End` | 焦点在表头某列的列宽手柄上时生效；`←` 变窄、`→` 变宽，每次 16px，`Home` / `End` 到该列最小 / 最大 |
| 恢复单列默认宽度 | 双击列宽手柄 / `Delete` / `Backspace` | 只复位该列，其它三列保持各自宽度；差异全空时整键移除 |
| 恢复全部分隔条默认 | 双击分隔条 / `Delete` / `Backspace` | 清掉存储值，回到样式表的比例默认 |

面板的键盘处理挂在两个滚动容器上，只在焦点落在栏内时生效，不向全局注册；带修饰键的组合一律不接管，留给宿主的快捷键目录。顶栏浮层的键盘处理只作用于浮层自己的搜索框和文档级 `Esc`。

## 已知边界

- 面板仍是只读视图：`run` 端点没有实现，暂存、提交、reset 都不在这里做。唯一的写操作是顶栏切换本地分支。
- 分支清单只列本地分支：不列远程跟踪分支，也不自动建跟踪分支。`--no-guess` 之后，只在 `origin` 上存在的名字不会被悄悄建成同名本地分支，需要先在终端里 checkout 或 `git branch --track`。
- 自动 stash 只负责切换前后的保存与放回：不做自动合并，冲突时改动留在 stash 条目里等人工处理；也不清理 stash 列表（本插件创建的条目带 `git-explorer: 切换 <分支> 前自动暂存` 说明，需要时自行 drop）。
- 被另一个工作树检出的分支在浮层里禁用，键盘也会跳过：判定来自 `git worktree list --porcelain` 与当前工作树根的字符串比较。
- 单条命令 20s 超时、4MB 单流预算。超大仓库的第一次 `git log` 可能先撞超时；stdout 被截断时查询整体失败，不会拿半页数据画一张缺边的图。
- 首屏只取 400 条提交；更早的历史要点"加载更多"，按 100 条递增，单次请求硬上限 5000，`skip` 上限 1000000。
- ref 过滤是白名单：分支、标签、提交名可用，`HEAD~3` 这类修订语法与 `..` 范围不进来。
- 宿主半需要 `subprocess`、`sessions`、`sessionPersistence` 三个服务；缺 `subprocess` 时服务构造即失败，客户端会显示"Git 服务不可用"。
- 提交详情文件清单是可读入口：悬浮给该提交版本的轻量预览，点击交给文件工作台打开同版本面板；两条路径都只读。
- 仓库目录取自会话的工作目录，会话没绑定目录时回落到宿主默认目录；不是仓库就给空态，不猜父目录。
- 窄窗（≤720px）只隐藏竖向分隔条：那里变更栏与右栏已经上下堆叠，横向分割没有可拖的轴，存储的宽度随样式表规则失效但不会被清除。行分隔条在窄窗照常可用，因为右栏内部「历史 / 详情」始终是竖直方向的分割，换窗口宽度不影响它要分的那个轴。窄窗同时隐藏历史栏的作者列，表头与数据行的 grid 模板同步少一列，否则隐藏后每个标签都会错位；作者列的手柄随单元格一起消失。
- 历史列宽是全局的：一份宽度对所有会话、所有仓库生效，不按仓库区分。未提交行只在工作区脏时出现，干净时不留空行占位。搜索态下该行仍然显示，因为「工作区有未提交改动」是面板常驻事实，与当前查询无关；它不参与「这一页是哪个查询的第几页」的推导，分页与行索引仍以提交数组为准。
- 行分隔条的高度百分比以右栏高度为分母。窗口改变高度时详情跟着等比缩放，这正是按比例存的目的；代价是拖到一个极矮的窗口时，`180px` 的地板可能占掉超过存储比例的高度。

## 结构

宿主半在 `src/host/`：`parse.ts`（log / refs / porcelain v2）、`lanes.ts`（泳道）、`git.ts`（argv runner 与预算）、`snapshot.ts` / `query.ts` / `detail.ts` / `show.ts` / `branches.ts` / `switch.ts`（六个数据端点，`switch.ts` 是唯一的写路径）、`failure.ts`（错误码）。客户端 `model.ts` 负责分组、图布局、行窗口与提交跳转，`cursor.ts` 是两栏共用的键位表与光标落点/跟随计算，`filter.ts` 是变更栏的路径过滤，`history-query.ts` 把「当前这一页是哪个查询的第几页」变成一个请求构造函数（搜索与分页共用它，所以分页不会丢掉查询），`pane-width.ts` 与 `detail-height.ts` 分别是竖向与横向分隔条的存储、夹取与键位翻译（纯函数，测试注入 store），`history-columns.ts` 是历史栏四列的宽度模型与稀疏持久化（同样纯函数、同样可注入 store），`working-tree-pane.tsx` 是选中未提交行时的右栏工作区摘要，`view.tsx` 只做装配、拖拽与跳转；顶栏分支面在 `branch-action.tsx`（触发器与浮层）、`branch-search.ts`（子序列匹配与光标移动）、`branch-store.ts`（客户端半共享的分支清单与 revision）。判据脚本从 `lib/index.js` 取 `__test`，在没有宿主上下文的情况下驱动解析与泳道。
